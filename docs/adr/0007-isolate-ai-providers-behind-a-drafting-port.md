# Isolate AI providers behind capability ports

Every AI workflow depends on the application-owned `DraftingProvider` capability interface rather than provider-specific clients. Provider adapters own transport and response translation; the deep orchestration module owns configuration, credentials, local validation, and the fixed OpenRouter → Gemini → Groq fallback policy. Users choose one curated model for each stage during onboarding or in Settings without changing workflow code. Provider Readiness requires all three encrypted credentials, all selected models to validate, and one explicit confirmation that the complete route must use only OpenRouter `:free` models, Gemini with billing disabled, and Groq on Free Plan. Changing any credential or selected model clears that confirmation. OpenRouter validation sends no user content and rejects a selected model unless its current catalog entry is zero-priced, ends in `:free`, and supports structured responses. A Foreground AI Job tries each stage once for credential, quota, transport, availability, model, or provider-response failures; cancellation, invalid input, unsupported layouts, local context overflow, and provider-independent safety failures never fall back. Each complete provider stage—including any schema-repair request—has one aborting deadline: 20 seconds for OpenRouter, 30 seconds for Gemini, and 20 seconds for Groq. A stage timeout is provider unavailability and advances to the next provider, while explicit user cancellation stops the entire route. The Vercel AI SDK is suitable for generic generation, but it is not added here: the existing port is smaller for a browser extension and keeps catalog-price checks, selected-model validation, exact fallback order, and provider-specific repair behavior explicit.
